How AgentOnCall works

Everything you need to get your first agent connected, and to understand what you are looking at.

The one-sentence version. Agents do work for you, and AgentOnCall is the place they check in with you before they do anything that matters — so a human decides, not the agent.

Reviewing an approval

Open Approvals. Each waiting request shows what the agent wants to do and, importantly, what the effect would be. That declaration is what you are approving — not a blank yes.

Approve lets the agent continue.

Reject stops the task and marks it failed. The agent is told the answer.

Approving does not override a stopped workspace. If the workspace is stopped, an approved task still waits until you reopen it.

Connecting a real agent

Two ways in, depending on what you are building.

REST API. Send your key in the Authorization header on every request. The key selects your workspace, so you never pass an account id.

MCP. If your agent speaks the Model Context Protocol, point it at our adapter and the whole task lifecycle becomes tools it can call.

When an agent goes quiet or overspends

AgentOnCall watches for two things: an agent that has stopped reporting in, and a task that has spent more than the budget you set. In both cases the task is marked halted, the agent is marked halted, and an incident is opened so there is a record.

A halt is a signal, not a kill switch. It is the connected integration's job to check the status before its next action and stop. That is why we ask you to read the status before every external action when you build an integration.

Alerts

In Settings → Alerts you can send notifications to a Slack channel or to your own webhook. They fire when an agent asks for approval, when an incident is opened, and when a workspace is stopped.

Webhooks are signed, so your receiver can verify the message really came from us before trusting it. The signing secret is write-only — we never show it back to you.

Delivery is best effort: each alert is sent once, never retried, and never blocks the action that triggered it. Treat alerts as a prompt to check the dashboard, not as a guaranteed record.

Stopping everything

Settings → Workspace controls → Stop workspace halts the whole workspace. New work cannot be claimed, active tasks are marked halted, and an incident is recorded. Reopening is a separate, deliberate step — nothing resumes on its own, and each halted task needs to be restarted individually.

Questions people actually ask

?

I forgot my password. How do I reset it?

You cannot, yet. There is no password reset and no email is sent from this product, so there is no self-service way back into an account. If you are locked out, whoever runs your AgentOnCall instance has to help you directly. We would rather say this plainly than have you discover it at the sign-in screen.

?

Can I invite a colleague?

Not yet. One workspace currently has one operator, so there is no way to add a second person or give someone a read-only view. If more than one person needs to approve things, you will each need your own workspace for now.

?

My agent says it cannot connect.

Check three things in order: that the key is complete and has not been revoked, that the workspace has not been stopped, and that the agent is pointed at the right address. A stopped workspace refuses new work, which looks like a connection problem from the agent's side.

?

My agent ran, but I see nothing.

Look in Approvals first — a request waiting for you does not appear anywhere else. If it is not there, open Tasks and check that task's activity; a rejected or failed task records why.

?

My alert never arrived.

Delivery is best effort and is never retried, so a single missed alert is expected behaviour rather than a bug. Use Send test alert to check the destination is right, and remember the address must be a public https URL — we refuse internal addresses on purpose.

?

Does this stop an agent that ignores you?

No, and it is worth being clear about that. Everything here is cooperative: an agent that never asks permission, or that ignores a halt, is not physically prevented from acting. What you get is that well-behaved agents pause for you, and that every request and every decision is recorded.

What this platform does not do

Being straight with you

So you are not surprised later:

  • No password reset, and no email of any kind — no verification, no notifications by mail.
  • One operator per workspace; no roles, no invitations.
  • Enforcement is cooperative. An agent that ignores the API is not stopped by it.
  • Alerts are best effort, with no retries and no delivery log.
  • Notifications are one-way. Approvals happen here in the dashboard, not in Slack.
